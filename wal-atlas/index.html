Every way the WAL breaks

Every part of PostgreSQL depends on the write-ahead log, and four independent consumers decide when a segment can go. Almost every WAL incident is the same story: one consumer stopped, and nobody was watching the log pile up.

The four gates

why a 16 MB file won’t go away

WAL is written as 16 MB segment files in pg_wal/. A segment can be recycled only when all four gates below have finished with it. The slowest gate sets the size of your log directory.

Gate 1

Checkpoint

Redo must have advanced past the segment. Until dirty pages are written, the segment is still needed for crash recovery.

Gate 2

Archiver

With archive_mode on, the segment must ship successfully. A failing archive_command holds every segment behind it.

Gate 3

Replication slots

Each slot’s restart_lsn pins the log. A slot whose consumer is gone pins it permanently, and slots survive restarts.

Gate 4

wal_keep_size

A fixed floor of retained WAL for standbys without slots. A deliberate reserve, not a safety net for the other three.
